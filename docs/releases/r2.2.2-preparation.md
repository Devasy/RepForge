## User-visible scope

Daily Programs flow: open the followed program, see its next unfinished workout,
and start or resume it. Choosing a saved program to follow is a one-time explicit
action. Progress derives from nonempty saved sessions linked to exact program,
week and day IDs. Cancellation and failed/empty saves never advance a day.
The selected program and workout draft survive restart. Deleting a linked
session makes that day unfinished again. Saved plan edits retain identity.

Secondary flows remain discoverable: view the schedule and completed days,
choose another program to follow, create offline, import JSON, optionally
AI-generate, edit, export or delete. One labelled action sheet replaces the
three floating controls. Narrow layouts and large text have synthetic previews.

The Programs changes use main's existing components/tokens. No PR95 theme,
Home, Activity, Analytics or workout-logging UI changes are included. Existing
workout conflict handling is reused. Concurrent Start/Resume operations are
serialized per provider until navigation returns.

## Compatible persistence

SQLite schema 8 adds nullable program_id, program_day_id and program_week_number
to sessions; existing rows remain unknown, with no guessed completion backfill.
Migration checks existing columns to handle already-upgraded schema fixtures.
Session JSON, copyWith, Hive fallback, SQLite save/load, backup serialization and
workout drafts preserve context. The following choice is a settings entry,
programs.followedId. Programs are still user-owned records through ProgramManager.

Program completion means the user finished and saved a nonempty workout, not
that every prescribed set was verified. Week/day order is retained and prescribed
weekdays are displayed; calendar rescheduling and repeat-cycle tracking are not
implemented. Historical sessions stay intact and unlinked.
