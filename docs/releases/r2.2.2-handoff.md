## Findings to preserve as regression requirements

Real-data review found correct retrieval did not guarantee correct conclusions:

- A middle-history peak can be omitted from a bounded recent history and ignored even when PR metadata contradicts a plateau claim.
- Independent PR maxima must never become a fictional observed weight×reps pair/date.
- Compare defined early/recent periods, not a weak first set chosen to inflate gains.
- Null handles and legacy load encodings are unknown unless evidence/user confirmation establishes meaning.
- Missing exported records are not proof of no training, no sleep, poor adherence or a disconnected device.
- Recovery percentages are estimates, not training clearance.
- Pain explanations, fixed “safe” joint angles, tendon-healing protocols and precise muscle-up deadlines were overconfident in actual answers. Add evidence-calibrated guidance, not canned assurances.
- Goal plans should use recent tolerable performance and uncertainty, not immediately increase load, set count and effort together.
- Preserve useful evidence/partial results when a model request fails after tool execution.
- Charts must have dates, units, meaningful comparable series and a short description/uncertainty/action based on the SAME structured evidence. This is the user's desired experience, not an implemented universal contract yet.

Longer term the user wants a reusable analytics assistant for other apps. Keep orchestration independent from app schema/metric definitions; typed evidence and presentation contracts are a better foundation than assuming arbitrary SQL automatically yields truthful analysis. Do not publish a general-quality claim before evaluation on RepForge and another dataset.
