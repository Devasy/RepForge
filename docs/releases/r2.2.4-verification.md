# r2.2.4 scoped Health Connect rollback

Branch `r2.2.4` starts at refreshed `origin/main` commit
`96387a5bc4e0d888eb9dc7ddaf2a55cd2ddabb15`. Local version: `2.2.4+75`.

## Scope

- Remove declared and requested skin-temperature read access and granted-type reporting.
- Disable direct skin-temperature reads, ingestion and watermark advancement, even when an old grant remains.
- Retain pre-existing HRV permissions, reading and readiness behavior; retain sleep, HR, RHR and workout/history access.
- Preserve generic pagination, persistence failure handling, history backfill, exercise catalogue, intensity maps, imports and other r2.2.3 fixes.
- Keep SQLite migrations, stored health data and existing backup compatibility unchanged. Existing health samples are local data; the backup format does not export health samples.
- Limit Profile copy to supported collection and Coach guidance to existing saved temperature data. New Home HRV/temperature graphs remain deferred to r2.3.0.
- Keep published r2.2.3 notes intact and add a separate 2.2.4 entry.

## Release follow-through

No Play Console declarations, tracks, live device data or release publication have been changed or verified by this implementation.

Inspect affected bundles and tracks, discard noncompliant drafts, and replace affected versions without retaining the old bundles. Confirm the specific testing track and rollout before changing it; do not promote silently.

Confirm actual uploaded Play version codes and a new unused workflow run number before uploading or retrying; rerunning an existing workflow keeps its number. Local `+75` is release preparation, not proof of an unused Play version code.

Reviewer path for retained HRV: Profile → Readiness insights → grant access → Home → readiness card → details. It needs real readings, at least five baseline days in the prior 14 days, and a reading within the last 48 hours. The deferred raw-HRV graph is not part of this release.
